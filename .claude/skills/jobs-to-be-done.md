# Jobs-to-Be-Done

Understand user motivations using the JTBD framework.

## Core Insight

Clayton Christensen and Tony Ulwick: people hire products to get a job done — focus on the job, not the product. The job statement format: "When [situation], I want to [motivation], so I can [expected outcome]."

## Three Dimensions

- **Functional**: The practical task or measurable outcome users seek to achieve
- **Emotional**: The psychological state users want to experience or avoid
- **Social**: How users wish to be perceived within their social context

## Process

1. **Uncover the fundamental job**: What is the core task the user is trying to accomplish? Look past product features to underlying motivation.
2. **Map functional dimensions**: What does success look like practically? What are the outcome expectations?
3. **Map emotional dimensions**: How does the user want to feel? What anxieties are they trying to avoid?
4. **Map social dimensions**: How does this affect how others perceive them?
5. **Chart the job lifecycle**: Map eight stages — define, locate, prepare, confirm, execute, monitor, modify, conclude. Find where current solutions fail.
6. **Clarify success criteria**: For each dimension, what does "job done" look like?
7. **Document current solutions**: How are users getting this job done today? What workarounds exist?
8. **Identify gaps**: Where does the current solution fail to fully serve the job?
9. Present findings with actionable design recommendations.
